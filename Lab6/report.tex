\section{Introduction}
The goal of this lab was to explore thread-level parallelism on a single node using OpenMP. We implemented and measured three variants of a counting workload: using a reduction clause, using a critical section to protect a shared counter, and performing parallel initialization followed by per-thread accumulation. We compare performance across 1, 2, 4, and 8 threads and discuss trade-offs.

\section{Discussion}
Measured results show that the \texttt{reduction} approach gives the best performance due to reduced synchronization overhead. The \texttt{critical} approach serialises access to the shared counter and suffers from contention as threads increase. The \texttt{parallel init} variant can improve scalability if per-thread work dominates initialization overhead.

Key factors affecting scaling:
\begin{itemize}
  \item Serial fraction (Amdahl's law)
  \item Synchronisation and contention (critical sections)
  \item Memory bandwidth and cache effects
  \item Thread start-up/teardown costs (parallel regions)
\end{itemize}

\section{Conclusion}
OpenMP provides concise constructs for parallelising loop-based workloads. Use \texttt{reduction} when combining simple scalar results for best performance; avoid fine-grained critical sections where possible. This lab reinforced practical considerations in writing parallel code: minimise synchronization, favour work partitioning and per-thread private data, and measure on target hardware. The \texttt{reduction} pattern is both simple and efficient for common associative operations.
